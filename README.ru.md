## Происхождение: Из горнила в металл



Мой путь в программировании укоренен в низкоуровневой системной архитектуре и экстремальной оптимизации. В 2015 году я изложил свое видение создания децентрализованных высокотехнологичных возможностей на африканском континенте в [этом трактате о Кремниевой долине Кении](https://www.linkedin.com/pulse/building-kenyas-silicon-valley-making-work-kevin-chege/). Когда в 2023 году началась золотая лихорадка LLM, я был одним из первых. Я создавал и развертывал оболочки для LLM, но быстро осознал их ограничения, о чем свидетельствует эта ранняя [демонстрация LLM-оболочки 2023 года](https://www.linkedin.com/feed/update/urn:li:activity:7102930955807449088/).

Я понял, что создание высокоуровневых абстракций поверх нестабильных API — это архитектурный тупик. Настоящая битва ведется на стыке ограничений локального оборудования и распределения ресурсов.

На протяжении всего 2025 года я жил на ноутбуке Lenovo X13 ThinkPad с крайне ограниченным профилем оборудования:

```
Процессор: AMD Ryzen 5 PRO 4650U (6 ядер, 12 потоков)
Графика: AMD Radeon RX Vega 6 iGPU
Память: 32 ГБ RAM (с высоким уровнем утилизации системы)
Накопитель: 256 ГБ NVMe (заполнен на 99%)
```

На этой самой машине в 2025 году я создал **Tumz** ([Sarafakai](http://www.sarafakai.com)) — изолированный (air-gapped) ИИ для поддержки принятия клинических решений с нулевой задержкой. Он одновременно выполнял распознавание речи в реальном времени и клинические выводы на интегрированном графическом процессоре (iGPU), удерживая всю Единую медицинскую языковую систему (UMLS) в оперативной памяти. В настоящее время мы сотрудничаем с кенийской больницей для проведения годового клинического испытания Tumz — ведь человеческое здоровье требует строгого эмпирического подтверждения, а не предположений разработчиков.

При разработке Tumz я столкнулся с колоссальной системной неэффективностью современного стека обработки данных:
1. **Налог на Python**: Постоянное копирование памяти между процессами, узкие места GIL и огромные накладные расходы времени выполнения.
2. **Налог на браузер**: Сложности Manifest V3, задержка рендеринга и высокочастотные сбои связи при длительных сессиях ИИ-агентов.
3. **Узкое место ядра ОС**: Неэффективное планирование процессов, голодание потоков процессора и накладные расходы дисплейного сервера (переключение контекста Wayland vs. X11).

Поэтому в конце 2025 года я решил создать инфраструктурный стек, который полностью обходит эти ограничения, — операционную систему агентов (Agentic OS), разработанную для конвейеров данных с нулевым копированием и аппаратного запуска ИИ. Этот репозиторий является открытым ядром этого движка.

## Ключевые особенности

* **Использование компьютера без пикселей**: Обход медленных и дорогих визуальных конвейеров агентов. Взаимодействие с рабочим столом Linux напрямую через AT-SPI2 и алгоритм сжатия TOON (Token-Oriented Object Notation), отправляющий необработанные иерархические деревья непосредственно в LLM.
* **Загрузка с нулевым копированием**: Аппаратно ускоренная загрузка данных в обход ядра с использованием `io_uring` и огромных страниц памяти размером 1 ГБ (Huge Pages).
* **Аппаратно ускоренная визуализация**: Интерактивное построение графиков Jupyter с малой задержкой с помощью демона рендеринга `lagos-lite`, созданного на базе `wgpu` и `egui`.
* **Векторизованное аналитическое выполнение**: Максимальная загрузка процессора благодаря выполнению запросов Polars и многопоточным конвейерам данных Rayon.
* **Суверенный интерфейс**: Удобный API Python (`SovereignFrame`), инкапсулирующий проецируемые в память файловые дескрипторы и IPC.

## Сравнение архитектур: Open Source и Enterprise

Архитектура Nairobi OS разделена. Открытый репозиторий предоставляет базовые механизмы высокопроизводительной обработки данных и примитивы визуализации на одном узле. Закрытая коммерческая экосистема содержит передовые мультиагентные решения повышенной доступности, ориентированные на промышленный сектор.

```
                                  +---------------------------------------+
                                  |         Nairobi Python API            |
                                  +---------------------------------------+
                                                      |
                                     [ GVariant через D-Bus / общая память  ]
                                                      |
                                                      v
                                  +---------------------------------------+
                                  |           Nairobi Hub                 |
                                  +---------------------------------------+
                                                      |
                    +---------------------------------+---------------------------------+
                    |                                                                   |
                    v                                                                   v
     +------------------------------+                                    +------------------------------+
     |     Axum Refinery (Данные)   | <===[ Zero-Copy IPC / iceoryx2 ]===> |     Lagos Vision (Визуал)    |
     +------------------------------+                                    +------------------------------+
```

### Open Source Crate Workspace (`crates/`)
1. `nairobi-axum-refinery` — Rust daemon managing raw data ingestion, Rayon-parallelized statistics, and Polars-vectorized query execution.
2. `nairobi-hub` — Central IPC orchestrator; routes file descriptors and signals between clients and the refinery daemon.
3. `lagos-lite` — Local/headless rendering engine using egui/wgpu hardware acceleration with zero-copy mmap data access.
4. `nairobi-protocol` — Shared protocol layer: GVariant serialization schemes, error types, and shared-memory layouts.
5. `nairobi-python` — The Python extension module, compiled via PyO3 and packaged with Maturin (`nairobi-os`).
6. `nairobi-canvas` — Immediate-mode node-graph compiler with hardware-accelerated UI (wgpu/egui), including a native file picker and SQL query presets.
7. `nairobi-connector` — Model Context Protocol (MCP) server and AT-SPI2 semantic accessibility bridge exposing TOON representations for LLM agents.
### Закрытая экосистема предприятия (`modules/`)

Наши корпоративные компоненты содержатся в приватном репозитории (`Sovereign-Systems-Lab`) и лицензируются для применения в промышленности, финансах и государственной инфраструктуре.

1. **`sovereign-ui`**: Корпоративный движок AT-SPI2. Реализует безопасность протокола Aegis, аппаратную привязку и управление рабочим столом промышленного класса.
3. **`tactical-rtos-node`**: Планировщик операционной системы реального времени с ультранизкой задержкой для критически важной автоматизации edge-устройств.
4. **`industrial-guardian-rust` / `industrial-guardian-python`**: Автономный уровень обеспечения надежности систем (SRE) с предиктивным предотвращением OOM, утечек памяти и сбоев системы.
5. **`fintech-bridge-rust`**: Парсер высокочастотных транзакций в реальном времени и мост к устаревшим мейнфреймам (парсинг терминалов EBCDIC/SBA).
6. **`aviation-audio-rust`**: Безблокировочная обработка аудиопотоков с субмиллисекундной задержкой, акустический телеметрический анализ и цифровая обработка сигналов (DSP).
7. **`drawbridge_api`**: Защищенный gRPC-шлюз с поддержкой авторизации, изолирующий локальное ядро от вызовов ненадежных облачных агентов.

### Матрица сравнения возможностей

| Возможность / Функция | Открытое ядро (`crates/`) | Набор Enterprise (`modules/`) |
| :--- | :---: | :---: |
| **Движок импорта** | `mmap` / `copy_file_range` | `io_uring` + `SQPOLL` + 1ГБ Huge Pages |
| **Статистический анализ** | Базовая описательная статистика | Векторизованный расчет асимметрии/эксцесса, корреляции |

## Установка и настройка

### Требования
- **ОС**: Linux (рекомендуется Ubuntu 22.04+) или подсистема Windows для Linux (WSL2).
- **GPU**: Драйвер с поддержкой Vulkan, Metal или OpenGL.
- **Python**: 3.10 или новее.
- **Rust**: Стабильный тулчейн (при сборке из исходников).

### Быстрая установка (PyPI)
```bash
pip install nairobi-os
```

### Сборка из исходного кода
Чтобы скомпилировать всю рабочую область, включая нативные демоны и расширение Python:

1. **Клонирование репозитория**:
   ```bash
   git clone https://github.com/KevinKenya/nairobi-connector-open-source.git
   cd nairobi-connector-open-source
   ```

2. **Настройка виртуального окружения**:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install maturin pyo3-build-config zbus anywidget traitlets pandas
   ```

3. **Запуск сборки рабочей области**:
   ```bash
   chmod +x build_wheel.sh
   ./build_wheel.sh --release
   ```
   Это скомпилирует нативные демоны, скопирует их в директорию пакета и соберет wheel в `crates/nairobi-python/target/wheels/`.

## Руководство по использованию

### 1. Аналитика данных (in-memory конвейер)

Nairobi OS предоставляет удобный API `SovereignFrame`. Он скрывает за собой детали низкоуровневого отображения памяти, обеспечивая сверхбыструю работу с данными.

```python
import nairobi_os as nb

# Запуск фонового демона refinery
nb.connect()

# Загрузка данных с использованием канала с нулевым копированием
frame = nb.read_csv("simulator/fndds_ingredient_nutrient_value.csv")

# Выполнение векторизованных расчетов в Rust refinery
profile = frame.crunch("value")
print(f"Среднее: {profile['mean']:.4f}")
print(f"Станд. откл.: {profile['std_dev']:.4f}")

# Выполнение произвольных SQL-запросов на отображенной в памяти таблице
subset = frame.query("SELECT * FROM dataset WHERE value > 50.0")

# Вызов интерактивного виджета визуализации, ускоренного Lagos
subset.plot(column="value")
```

### 2. Использование компьютера без пикселей (MCP)

Чтобы использовать семантический интерфейс AT-SPI2, ваш ИИ-агент должен взаимодействовать с доступными инструментами MCP-сервера вместо анализа скриншотов:

```
                  ПОСЛЕДОВАТЕЛЬНОСТЬ ВЗАИМОДЕЙСТВИЯ
                     
  [ ИИ-Агент ]                                  [ Nairobi OS ]
        |                                             |
        |===> nairobi_find_window("Text Editor") ====>| (Поиск окна)
        |<=== Возвращает ID окна и его границы =======|
        |                                             |
        |===> nairobi_get_ui_map() ==================>| (Генерация TOON)
        |<=== Возвращает сжатое дерево Markdown ======|
        |     "[ID: 12] Button: 'Save'"               |
        |                                             |
        |===> nairobi_interact(12, "click") =========>| (Выполнение действия)
        |<=== Возвращает статус успешности ===========|
```

## Настройка системы (руководство для разработчиков)

Чтобы достичь профилей производительности, показанных в наших тестах, ядро вашего хоста должно быть настроено для системного отображения памяти.

### Страницы памяти размером 1 ГБ (Huge Pages)
Nairobi OS использует Huge Pages размером 1 ГБ, чтобы избежать накладных расходов трансляции буфера ассоциативной трансляции (TLB) процессора на массивных наборах данных.

Чтобы выделить Huge Page на хосте Linux:
```bash
echo 1 | sudo tee /sys/kernel/mm/hugepages/hugepages-1048576kB/nr_hugepages
```
*Примечание: Если система не может выделить страницу размером 1 ГБ из-за фрагментации, движок автоматически переходит на использование Transparent Huge Pages (THP).*

### Настройка D-Bus Broker
В высокочастотных средах убедитесь, что установлен `dbus-broker` вместо устаревшего `dbus-daemon` для обеспечения максимально быстрой передачи сигналов по всей управляющей шине.
