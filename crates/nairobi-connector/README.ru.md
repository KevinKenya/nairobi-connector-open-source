# Nairobi Connector

## Обзор
**Nairobi Connector** — это семантический мост AT-SPI2 и сервер протокола контекста модели (Model Context Protocol, MCP) для Nairobi OS. Он обеспечивает **«использование компьютера без пикселей»**, предоставляя дерево доступности рабочего стола Linux для LLM и ИИ-агентов в сверхплотном, оптимизированном по токенам формате, известном как TOON (Token-Oriented Object Notation). Работая исключительно на семантических узлах интерфейса, а не на пикселях, он обеспечивает практически мгновенное выполнение действий и кардинально снижает расход токенов.

## Ключевые особенности
- **Использование компьютера без пикселей**: Прямое взаимодействие с рабочим столом Linux через AT-SPI2, исключающее необходимость в скриншотах, распознавании текста (OCR) или визуальной обработке.
- **Алгоритм сжатия TOON**: Преобразует необработанные деревья доступности D-Bus в высокосжатое представление Markdown. Он отфильтровывает неинтерактивные узлы «шума» и присваивает последовательные идентификаторы интерактивным элементам, обеспечивая вывод < 500 токенов менее чем за 50 мс.
- **Интеграция с сервером MCP**: Реализует надежный сервер на основе библиотеки `rmcp`, предоставляющий семантические инструменты непосредственно совместимым агентам LLM.
- **Безопасный жизненный цикл сессии**: Включает мониторинг активности (heartbeat) для предотвращения зависания ОС путем автоматического освобождения блокировки `RegistryLock` при обрыве stdio-потока.

## Архитектура
Коннектор действует как двунаправленный мост между LLM (через MCP) и рабочим столом Linux (через AT-SPI2/D-Bus). Он оборачивает слой `NeuralSession`, управляя обнаружением окон, обходом дерева пользовательского интерфейса и локальной инъекцией действий.

### Предоставляемые инструменты MCP
- `nairobi_find_window`: Находит целевое окно по подстроке заголовка (без учета регистра).
- `nairobi_get_ui_map`: Возвращает текущее дерево доступности интерфейса в виде карты, сжатой в формате TOON. Создает плотный список интерактивных элементов (кнопок, полей ввода, чекбоксов) с последовательными тегами `[ID: N]` для взаимодействия.
- `nairobi_interact`: Выполняет семантические действия (`click`, `activate`, `focus`) на элементе интерфейса, используя его идентификатор узла TOON.
- `nairobi_type_text`: Атомарно вводит текст в редактируемое поле (Entry, TextArea), определенное по его идентификатору узла TOON.

## Использование
Агенты, использующие Nairobi Connector, должны следовать следующему основному циклу:
1. Выбрать целевое окно с помощью `nairobi_find_window`.
2. Получить текущую структуру интерфейса через `nairobi_get_ui_map`.
3. Считать тег TOON `[ID: N]` требуемого интерактивного элемента.
4. Выполнить действие на этом элементе с помощью `nairobi_interact` или `nairobi_type_text`.
5. Повторить действия, начиная с шага 2, чтобы получить свежие идентификаторы перед следующим взаимодействием.
