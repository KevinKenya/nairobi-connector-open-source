## 起源：ルツボから金属へ



私のプログラミングの旅は、低レイヤのシステムアーキテクチャと極限の最適化に根ざしています。2015年、私は[ケニアのシリコンバレーに関するこの論考](https://www.linkedin.com/pulse/building-kenyas-silicon-valley-making-work-kevin-chege/)で、アフリカ大陸に分散型で高度な技術力を構築するビジョンを示しました。2023年にLLMゴールドラッシュが始まったとき、私は初期から参入していました。LLMラッパーを構築してデプロイしましたが、この初期の [2023年 LLM ラッパーデモ](https://www.linkedin.com/feed/update/urn:li:activity:7102930955807449088/)に記録されているように、その限界をすぐに認識しました。

不安定なAPIの上に高レベルのラッパーを構築することは、アーキテクチャ上の行き止まりであると痛感したのです。真の戦いは、ローカルなハードウェアの制約とリソースの割り当ての交差点で繰り広げられます。

2025年を通じて、私は非常に制約の厳しいハードウェア構成を持つ Lenovo X13 ThinkPad 上で生活し、開発を行っていました：

```
プロセッサ: AMD Ryzen 5 PRO 4650U (6コア, 12スレッド)
グラフィックス: AMD Radeon RX Vega 6 iGPU
メモリ: 32 GB RAM (システム使用率が非常に高い状態)
ストレージ: 256 GB NVMe (99% フル)
```

このまったく同じマシン上で、私は2025年、エアギャップ（オフライン環境）かつゼロ遅延の臨床意思決定支援AIである **Tumz** ([Sarafakai](http://www.sarafakai.com)) を構築しました。統合GPU (iGPU) 上でリアルタイムの音声文字起こしと臨床推論を同時に実行し、統一医学用語システム (UMLS) 全体を常にRAM上に保持しました。私たちは現在、ケニアの病院と提携して Tumz を1年間の臨床試験でパイロット運用しています。人間の健康には開発者の仮定ではなく、厳格かつ実証的な検証が必要だからです。

Tumz の開発中に、私は現代のデータサイエンススタックが抱える、構造的かつ深刻な非効率性に直面しました：
1. **Python 税**：エンドツーエンドのメモリコピー、GILのボトルネック、および巨大なランタイムオーバーヘッド。
2. **ブラウザ税**：Manifest V3 の複雑化、レンダリング遅延、および長時間の自律型エージェントの会話における高頻度の通信障害。
3. **OS カーネルのボトルネック**：非効率なプロセススケジューリング、CPUスレッドの枯渇、およびディスプレイサーバーのオーバーヘッド（Wayland vs X11 コンテキスト切り替え）。

そのため、2025年末に私は、これらの制限を完全にバイパスするインフラスタック、すなわちゼロコピーのデータパイプラインとハードウェアネイティブなAI実行のために設計された「エージェント指向オペレーティングシステム（Agentic Operating System）」の構築に着手しました。このリポジトリは、そのエンジンのオープンソースコアです。

## 主な機能

* **ピクセルなしのコンピュータ使用**：遅く高価なビジョンベースのエージェントパイプラインを完全にバイパスします。AT-SPI2 と TOON（Token-Oriented Object Notation）圧縮アルゴリズムを介して Linux デスクトップとネイティブに相互作用し、生の階層ツリーを LLM に直接フィードします。
* **ゼロコピーデータ接入**：`io_uring` と 1GB ヒュージページ (Huge Pages) を活用した、ハードウェア加速・カーネルバイパスの超高速データローディング。
* **ハードウェア加速ビジュアライゼーション**：`wgpu` と `egui` 上に構築された `lagos-lite` レンダリングデーモンによる、低遅延でインタラクティブな Jupyter プロッティング。
* **ベクトル化された分析実行**：Polars クエリ実行と Rayon マルチスレッドデータパイプラインを利用した、極限の CPU 飽和。
* **ソブリン（主権）インターフェース**：メモリマップされたファイル記述子と IPC をカプセル化する、使いやすい Python API (`SovereignFrame`)。

## オープンソース vs. エンタープライズアーキテクチャ

Nairobi OS は構造的に分岐しています。オープンソースリポジトリは、基本的な高性能データ処理とシングルノードのビジュアライゼーションプリミティブを提供します。クローズドソースの商用エコシステムには、高度なマルチエージェント、高可用性、および業界特化の高度な実装が含まれています。

```
                                  +---------------------------------------+
                                  |         Nairobi Python API            |
                                  +---------------------------------------+
                                                      |
                                     [ D-Bus / 共有メモリを介した GVariant ]
                                                      |
                                                      v
                                  +---------------------------------------+
                                  |           Nairobi Hub                 |
                                  +---------------------------------------+
                                                      |
                    +---------------------------------+---------------------------------+
                    |                                                                   |
                    v                                                                   v
     +------------------------------+                                    +------------------------------+
     |     Axum Refinery (Data)     | <===[ ゼロコピー IPC / iceoryx2 ]===> |     Lagos Vision (Visual)    |
     +------------------------------+                                    +------------------------------+
```

### オープンソース Crate ワークスペース (`crates/`)

1. **`nairobi-axum-refinery`**：生のデータインジェクション、Rayon 並列化統計計算、および Polars ベクトル化クエリ実行を管理する、高性能 Rust デーモン。
2. **`nairobi-hub`**：中央の IPC オーケストレーター。クライアントと refinery デーモン間のファイル記述子と信号の管理とルーティングを行います。
3. **`lagos-lite`**：視覚皮層。メモリマップされたファイル記述子を直接 GPU パイプラインにマップする、ヘッドレスなイベント駆動型レンダリングエンジン。
4. **`nairobi-protocol`**：共有プロトコルレイヤ。標準の GVariant シリアライズスキーム、エラータイプ、および共有メモリレイアウトを定義します。
5. **`nairobi-python`**：`PyO3` を介してコンパイルされ、`Maturin` でパッケージ化された Python 拡張モジュール。

### プライベートエンタープライズエコシステム (`modules/`)

当社のエンタープライズ層コンポーネントは、プライベートリポジトリ（`Sovereign-Systems-Lab`）に保管されており、工業、金融、および国家インフラ用にライセンスされています。

1. **`sovereign-ui`**：エンタープライズ向け AT-SPI2 エンジン。Aegis プロトコルセキュリティ、ハードウェアバインディング、および本番グレードのデスクトップ制御を実装。
2. **`nairobi-connector`**：高度なモデルコンテキストプロトコル（MCP）サーバー。エンタープライズ向け LLM に生の低遅延 D-Bus 信号を提供。
3. **`tactical-rtos-node`**：安全性が重要なエッジ産業オートメーション向け、超低遅延のリアルタイムオペレーティングシステム（RTOS）スケジューラー。
4. **`industrial-guardian-rust` / `industrial-guardian-python`**：予測的OOM、メモリリーク、およびシステムクラッシュの回避機能を備えた、自律的なサイト信頼性エンジニアリング（SRE）レイヤ。
5. **`fintech-bridge-rust`**：リアルタイムの高頻度取引パーサーおよびレガシーメインフレームブリッジ（EBCDIC/SBA 端末解析）。
6. **`aviation-audio-rust`**：サブミリ秒・ロックフリーのオーディオストリーム処理、音響テレメトリ分析、および生の波形 DSP。
7. **`drawbridge_api`**：ローカルカーネルを信頼できないクラウドエージェントコールから隔離する、安全で認証されたマルチテナント gRPC ドローブリッジ。

### 機能比較マトリクス

| 機能 / 特性 | オープンソースコア (`crates/`) | エンタープライズスイート (`modules/`) |
| :--- | :---: | :---: |
| **インジェクションエンジン** | `mmap` / `copy_file_range` | `io_uring` + `SQPOLL` + 1GB ヒュージページ |
| **統計分析** | 基本的な記述統計 | ベクトル化されたマルチパス歪度/尖度、相関分析 |
| **クエリエンジン** | プロセス内 Polars SQL | 分散型 Apache Arrow / DataFusion クラスター |
| **IPC メカニズム** | POSIX 共有メモリ / D-Bus | ゼロコピー `iceoryx2` 共有メモリ領域 |
| **可視化** | ローカル Jupyter `anywidget` | WebRTC GStreamer / 透明な Wayland Layer-Shell オーバーレイ |
| **セキュリティと準拠** | 標準の POSIX 境界 | Aegis プロトコル、SHA-256 チェーンフォレンジック元帳 |
| **認証** | なし (ローカルの信頼されたユーザー) | ハードウェアバインディング (TPM 2.0 / CPU ID), プライベート PKI |
| **プラットフォーム対象** | シングルノード Linux | 分散クラウド / エッジノード / 高頻度取引 |

## インストールとセットアップ

### 必要要件
- **OS**: Linux (Ubuntu 22.04+ を推奨) または Windows Subsystem for Linux (WSL2)。
- **GPU**: Vulkan、Metal、または OpenGL 互換ドライバ。
- **Python**: 3.10 以上。
- **Rust**: 安定版ツールチェーン（ソースからビルドする場合）。

### クイックインストール (PyPI)
```bash
pip install nairobi-os
```

### ソースからのビルド
ネイティブデーモンと Python 拡張を含むワークスペース全体をコンパイルするには：

1. **リポジトリのクローン**:
   ```bash
   git clone https://github.com/KevinKenya/nairobi-connector-open-source.git
   cd nairobi-connector-open-source
   ```

2. **仮想環境の設定**:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install maturin pyo3-build-config zbus anywidget traitlets pandas
   ```

3. **ワークスペースのビルド実行**:
   ```bash
   chmod +x build_wheel.sh
   ./build_wheel.sh --release
   ```
   これにより、ネイティブデーモンがコンパイルされてパッケージディレクトリにコピーされ、`crates/nairobi-python/target/wheels/` 以下に wheel が作成されます。

## 使用方法

### 1. データ分析 (インメモリパイプライン)

Nairobi OS は `SovereignFrame` API を提供します。これはバックグラウンドで生のメモリマッピングを処理し、超高速のデータ操作を可能にします。

```python
import nairobi_os as nb

# バックグラウンドの refinery デーモンを起動して接続
nb.connect()

# ゼロコピーメモリパイプラインを使用してデータセットを読み込む
frame = nb.read_csv("simulator/fndds_ingredient_nutrient_value.csv")

# Rust refinery を介してベクトル化された計算を実行
profile = frame.crunch("value")
print(f"Mean: {profile['mean']:.4f}")
print(f"Std Dev: {profile['std_dev']:.4f}")

# メモリマップされた frame 上で任意の SQL クエリを直接実行
subset = frame.query("SELECT * FROM dataset WHERE value > 50.0")

# Lagos 加速インタラクティブプロッティングウィジェットを表示
subset.plot(column="value")
```

### 2. ピクセルなしのコンピュータ使用 (MCP)

AT-SPI2 セマンティックインターフェースを使用するには、AI エージェントはスクリーンショットを解釈するのではなく、公開されている MCP サーバーツールと相互作用する必要があります：

```
                    コンピュータ使用シーケンス
                     
  [ LLM エージェント ]                             [ Nairobi OS ]
        |                                             |
        |===> nairobi_find_window("Text Editor") ====>| (ターゲットを検出)
        |<=== ウィンドウ ID とバウンズを返す =========|
        |                                             |
        |===> nairobi_get_ui_map() ==================>| (TOON を生成)
        |<=== 圧縮された Markdown ツリーを返す =======|
        |     "[ID: 12] Button: 'Save'"               |
        |                                             |
        |===> nairobi_interact(12, "click") =========>| (アクションを実行)
        |<=== 成功ステータスを返す ===================|
```

## システムチューニング (コントリビューターガイド)

ベンチマークに示されているパフォーマンスプロファイルを達成するには、ホストカーネルがシステムレベルのメモリマッピング用に設定されている必要があります。

### 1GB ヒュージページ (Huge Pages)
Nairobi OS は 1GB ヒュージページを使用して、巨大なデータセットに対する CPU のトランスレーションルックアサイドバッファ (TLB) トランスレーションオーバーヘッドを回避します。

Linux ホストでヒュージページを割り当てるには：
```bash
echo 1 | sudo tee /sys/kernel/mm/hugepages/hugepages-1048576kB/nr_hugepages
```
*注意：フラグメンテーションなどの理由によりシステムが 1GB ページを割り当てられない場合、エンジンは自動的に透過的ヒュージページ (THP) にフォールバックします。*

### D-Bus Broker の設定
高頻度環境では、制御プレーン全体での迅速な信号伝搬を保証するため、従来の `dbus-daemon` ではなく `dbus-broker` がインストールされていることを確認してください。
